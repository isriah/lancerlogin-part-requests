# LancerLogin Part Requests plugin v1.2.0

Part Requests now uses LancerLogin Core's shared Notion connection instead of keeping its own Notion token. Students notice nothing: requests, Carts and the recipient list work as before. For Admins, the token now lives in **Settings > Integrations > Notion**, where every module that uses Notion shares it, and the ordering database is chosen with Core's database picker on the Part Requests Connection tab.

Requires LancerLogin Core `>=2.1.0-beta.12 <3.0.0` (module SDK `^1.8.0`, module contract 1). No database migration, and no change to the extension.

## Updating from 1.1

Nothing needs doing in most installations. The first request, Carts read or recipient refresh after the update hands the token 1.1 saved to Core and clears the plugin's copy:

- **Core had no Notion connection:** Core takes the token and, once Notion confirms it, the same ordering database. Requests carry on.
- **Core already had a Notion connection:** Core keeps its own. If the ordering database isn't chosen for Part Requests yet, requests stop until an Admin opens **Settings > Modules > Part Requests > Connection** and presses **Use the previous ordering database** (or pastes the database's link). If Core's connection can't open it, share the ordering database with that connection in Notion, then try again.
- **The saved token can't be read** (for example after a restore onto another installation): save the token in **Settings > Integrations > Notion**, then choose the ordering database.

Core's connection needs Notion's **Read content**, **Insert content** and **Read user information** capabilities for this version. It never receives email addresses.

## Bugs fixed

None.

## Features added

- Part Requests uses Core's Notion connection (`services.notion`) with one declared database, `orders`, and only the operations it calls: reading the layout, querying rows and creating a page, plus listing and looking up workspace users.
- The Connection tab shows Core's connection, places Core's database picker, and offers **Use the previous ordering database** after the move.
- Requests pause, with nothing recorded, while Core holds every module's Notion writes (an Admin's Stop or a restore), and Carts serves its copy while Core waits out a Notion rate limit.

## Features removed

- The plugin's own Notion token: its entry, Replace and Remove on the Connection tab, and the `PUT /token`, `DELETE /token`, `POST /database` and `POST /connection` setup routes. `POST /verify` now takes an empty body and checks the database Core has chosen.
