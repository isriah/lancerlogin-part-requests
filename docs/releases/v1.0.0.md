# LancerLogin Part Requests plugin v1.0.0

The first stable release of Part Requests. Students send part requests to the team's Notion ordering database from the **Robotics Part Requests** Chrome extension, without signing in to LancerLogin. LancerLogin holds the Notion token, so it never reaches a student's browser.

Requires LancerLogin Core `>=2.1.0-beta.7 <3.0.0` (module SDK `^1.6.0`, module contract 1).

## What it does

- **Part requests:** a student opens a vendor's product page, reviews the details the extension filled in, picks a team and a recipient, and sends the request. The plugin creates the page in the team's Notion ordering database, with server-side duplicate protection and a warning when the same item was requested recently.
- **Pairing through Discord:** a student runs `/ordering-pin` in Discord and gets a private reply with the site address and a one-time PIN, valid for 10 minutes, to enter in the extension. Their Discord account must be linked to a roster member. Each member can pair a limited number of devices, and a device can unpair itself.
- **Carts:** the extension can read the team's open orders and fill a store's cart with them. It never checks out or pays; a person always finishes the order on the store's site. The plugin records who built a cart so others can see it. An Admin can turn Carts off.
- **Admin pages:** **Settings > Modules > Part Requests** has three sections:
  - **Connection:** the Notion connection and its token, with Replace and Remove, the database, the recipient list, pairing and the Carts switch. Any problem and its fix are shown at the top.
  - **Requests log:** every request with its member and device, newest first.
  - **Paired devices:** counts, search and filters, one row per member, and Revoke.

## Setup

1. **Install the plugin** from **Settings > Modules** on your LancerLogin installation.
2. **Connect Notion.** In Notion, create an internal integration with the **Read content** and **Insert content** capabilities, plus **Read user information without email addresses** so the recipient list can name workspace members. Add the integration to the ordering database. Then open Core's setup screen for Part Requests, paste the integration's token and the database's link, and press **Verify**. Verify checks the token and the database layout together and saves nothing if either fails.
3. **Pair students.** Each student installs the Robotics Part Requests extension, runs `/ordering-pin` in Discord and enters the PIN in the extension.

The expected database layout and the full route reference are in the repository's README.

## Companion extension

The Chrome extension is released separately as **Robotics Part Requests v1.0.0** at https://github.com/isriah/lancerlogin-part-requests-extension. Older extensions keep working and show a notice with the update link.

## Bugs fixed

- A Notion connection without the **Insert content** capability now stays on **Needs attention**. Before, a refused request was recorded as lost access, and the next successful read, such as a Carts refresh, the recipient refresh or a verify, cleared it, so Connection flipped between Needs attention and Connected. The problem now names the missing capability and where to turn it on, and clears only when a request creates a page or the token is replaced.

## Features added

- Part requests from the Robotics Part Requests extension into the team's Notion ordering database.
- Device pairing with `/ordering-pin` in Discord, per-member device limits, self-revoke, and per-device rate limits.
- Carts: open orders from Notion, including Incomplete Requests, through a short shared copy, and cart marks that record who built a cart. Carts fills store carts and never checks out.
- Admin pages for the connection, the requests log and paired devices, including one-step token replacement and clear messages when Notion rejects the token or access is lost.

## Features removed

None.
