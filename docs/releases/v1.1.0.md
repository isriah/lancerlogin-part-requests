# LancerLogin Part Requests plugin v1.1.0

Admins can now generate a pairing PIN for a member from the Part Requests settings page, so members without Discord can pair the **Robotics Part Requests** extension. Until now, `/ordering-pin` in Discord was the only way to get a PIN.

Requires LancerLogin Core `>=2.1.0-beta.7 <3.0.0` (module SDK `^1.6.0`, module contract 1). No database migration, and no change to the extension. Students should use **Robotics Part Requests v1.0.2** or later (https://github.com/isriah/lancerlogin-part-requests-extension/releases/tag/v1.0.2), which captures the option chosen on a store page.

## Generate pairing PIN

1. Open **Settings > Modules > Part Requests > Paired devices** and press **Generate pairing PIN**.
2. Find the member by name, choose them and press **Generate**.
3. Give the member the PIN and the site address, or press **Copy** to copy both. They open the Robotics Part Requests extension, enter the site address and the PIN.

The PIN is the same one `/ordering-pin` makes: 8 characters, works once, expires in 10 minutes, and counts against the member's device limit. Making a new PIN, from Discord or from this page, cancels that member's earlier unused PIN. The PIN is shown only once and disappears from the screen when it expires or when the window closes. Only its hash is stored. Each PIN adds an audit entry with the Admin, the member and the time, never the PIN.

A member already at the device limit can't get a PIN until an Admin removes one of their devices. A member off the active roster can't get one at all.

None.

## Features added

- **Generate pairing PIN** on the Paired devices section, with member search, the PIN in large type, its expiry time, the site address, short instructions, Copy and Generate another.
- `POST /admin/part-requests/pins`, Admin only from the dashboard, which returns a PIN for a chosen member and is rate limited to 30 PINs per Admin in 10 minutes.

## Features removed

None.
