# LancerLogin Part Requests plugin v1.3.0

Part Requests can now remind people about part requests left as Incomplete Requests. On the days an Admin chooses (Mon, Wed and Fri at 3 PM by default), every Incomplete Request older than the threshold (2 days by default) gets a Notion comment mentioning its Orderer/Recipient and a Discord message pinging them, and its Reminder sent date is set so it is not reminded again until the cooldown passes. The message reads: "Your part request '<Item Description>' has been in Incomplete Request for more than <N> days, so it has not been ordered. Finish the details and change the Status to NORMAL, RUSH or SLOW Request, or delete the request if you no longer need it."

Reminders are off until an Admin sets them up on the new **Reminders** tab in **Settings > Modules > Part Requests**. Requests, Carts and the recipient list work exactly as before.

Requires LancerLogin Core `>=2.1.0-beta.12 <3.0.0` (module SDK `^1.8.0`, module contract 1). One database migration (`0005_reminders.sql`), which adds the reminder tables. No change to the extension.

## Turning reminders on

1. In Notion, add **Created** (created time) and **Reminder sent** (date) to the ordering database, and check that Status has Incomplete Request, NORMAL Request, RUSH Request and SLOW Request.
2. In Notion's integration settings, turn on **Insert comments** and **Update content** for the connection saved in **Settings > Integrations > Notion**.
3. On the Reminders tab, press **Check ordering database**, optionally choose and check the People database, pick the Discord channel, turn reminders on and save. **Preview** shows what a run would do without sending anything.

## Features added

- Stale-request reminders: a Notion comment with mentions, a Discord message with pings, then Reminder sent, for each Incomplete Request older than the threshold, on a weekly schedule in the installation's time zone, with a cooldown between reminders.
- The Reminders tab: status and problems with their fixes, Check ordering database, Preview (a dry run), Send reminders now, the settings, the optional People database, and the last run, including requests with nobody set, skipped pings and comments to check.
- The optional, read-only People database (Core's `people` binding) matches each Notion person to a member by their LancerLogin member ID, so Discord pings the right member. Without it, pings use members' default recipients.
- The manifest now declares `comments.create` and `pages.update` on the ordering database, and the optional `people` binding with read operations only.

None.
